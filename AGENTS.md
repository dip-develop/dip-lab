# DIP-Lab

## Behavioral defaults

A comprehensive project system prompt is already injected via `.opencode/rules/system_prompt.yaml`. This file adds what that misses. Read both.

## Non-obvious commands

```bash
./manager.sh setup                    # Create Docker networks + data dirs (pre-start)
./manager.sh start databases          # ALWAYS first (all services depend on it)
./manager.sh start proxy              # Then Traefik
./manager.sh start                    # Then everything else (respects SERVICE order)
./manager.sh stop                     # Stops in reverse order
./manager.sh update [svc]             # docker compose pull + up -d
./manager.sh logs gallery --tail 100  # Follow + tail
./manager.sh perm                     # Fix UID/GID per service data dirs
./manager.sh full-cleanup             # nuke all containers/images/volumes/networks
```

## Services (startup order)

1. databases — PostgreSQL (pgvector:16), MySQL 8.0, Redis 7-alpine
2. proxy — Traefik v3.7 on ports 80/443, file config in `proxy/dynamic/` + `proxy/traefik.yml`
3. monitoring — Grafana, Prometheus, Loki, Promtail, cAdvisor, Node Exporter
4. passwords — Vaultwarden
5. dockerui — Portainer
6. cloud — Seafile
7. docs — Paperless-ngx
8. automation — n8n
9. gallery — Immich v2
10. llm — vLLM (CPU mode: `--device cpu --enforce-eager`, model `google/gemma-4-2b-it`)
11. aiagent — Hermes agent (`nousresearch/hermes-agent:latest`), web UI on port 18790

## Docker networking

- `web` — Traefik entrypoint (external-facing)
- `internal` — LLM + aiagent (isolated, no DB access)
- `database` — PostgreSQL, MySQL, Redis (shared, used by passwords/docs/automation/gallery)

## Traefik gotchas

- `exposedByDefault: false` — services MUST have `traefik.enable=true` label to be discovered
- File-based dynamic config lives in `proxy/dynamic/` (currently only `security.yml`)
- Dashboard htpasswd generated by `proxy/entrypoint.sh` from `.env` vars `TRAEFIK_DASHBOARD_PASS`
- All Traefik exposure labels are **commented out** in docker-compose files by default

## Data directory quirks

- `manager.sh setup` creates dirs + sets ownership — do not create them manually
- Gallery (Immich) requires `.immich` marker files in each subdirectory under `gallery/data/gallery/*/`
- UID mapping: automation → 1000:1000, cloud → 0:0, postgres → 999:999, mysql → 999:999, redis → 6379:6379
- Object storage at `/mnt/object-storage/data/` — enabled per-service via bind mount; skip if mount missing
- Data dirs are listed in `.gitignore` (`*/data/`)

## Service env pattern

Every service loads its own `.env` from its own directory. Cross-service secrets (DB passwords) are duplicated across `.env` files — they must stay in sync.

## Not obvious from filenames

- `opencode.json` filesystem MCP points to `/home/dimoshka/dm-home.de` (different repo!) — not this directory
- aiagent has a backward-compat `nginx:alpine` alias container named `aiagent-alias`
- vLLM runs on **CPU** by default (no GPU pass-through)
- No CI, no tests, no build step — pure `docker compose up -d` deployment
- Gallery/Immich references shared postgres + redis from the databases service — its `.env` must contain those credentials

## Sensitive (never commit)

All `*.env` files, `proxy/acme.json`, `proxy/logs/`, `proxy/certs/`, `proxy/dynamic/.htpasswd`, `*/data/` directories.
